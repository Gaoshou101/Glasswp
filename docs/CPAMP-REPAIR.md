# CPAMP 配额数据库修复

日期：2026-10-10。用户授权尝试修复部分账号快照的 `database disk image is malformed (11)`。

## 诊断与恢复

- 新生产主机及部署路径通过已有基础设施记忆和 SSH 实测确认。
- SQLite 在线 backup API 生成一致性副本，保留配置、密钥；所有试验先在副本执行。
- `integrity_check` 发现多个表的 B-tree 错误，以及配额与请求表交叉引用同一数据页。副本上的 `REINDEX` 失败。10 月 9 日的旧备份也含同样问题，未覆盖生产历史。
- 完整扫描读出全部有效历史请求；其 event_hash 集合与独立事件账本一致。6 条违反字段类型/非空约束的异常行逐一证明是其他表已有记录的错误重复引用，而非待删除的真实请求。
- 以原 schema 创建新库，复制 47 张业务表所有有效记录，保留 ID 和 sequence；按记录内容 SHA-256 核对每张表。唯一性或无法解释的异常会中止，不跳过真实记录。
- 重建普通索引及派生全文搜索索引；核对外键状态没有变化，完整性检查返回 `ok`，事件账本不存在缺失请求。
- 最终停服备份最新数据库，再执行同一验证恢复流程。通过后原子切换并启动 CPAMP；切换脚本含失败自动回退。CPA 网关继续运行。
