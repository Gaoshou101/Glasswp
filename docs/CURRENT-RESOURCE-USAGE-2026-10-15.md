# 当前资源占用检查

日期：2026-10-15，Asia/Shanghai。

## 结论

**当前正式桌面的 CPU、GPU 和显存负载符合轻量液态方案的预期量级，没有观察到明显超预算或持续内存增长。可以继续使用当前配置。**

内存需要区分口径：Web 壁纸的私有提交量平均约 **447 MiB**，私有工作集约 **160 MiB**，进程工作集合计约 **636 MiB**。后者明显高于两天前的短时记录，但包含共享页，不能直接视为本项目独占的物理内存增量。当前并未隔离这一变化的具体原因。

本次是当前使用状态观察，**不是固定负载的新旧版本 A/B 验收**，因此只能判断当前量级，不能证明液态效果本身增加或减少了多少资源。

- 正式 Wallpaper Engine 桌面，1600×2560、30 FPS、未暂停；三个区域材质均为透明度 83、模糊 26、高光 68。
- 一组 Web 壁纸，共 5 个 CEF 进程；桥接、WE 主程序与其他屏幕场景、Windows 桌面合成器分别统计。
- 主采样：13:48:37–13:50:28，约 111 秒、30 个有效区间。
- 内存追加采样：13:51:39–13:53:45，约 125 秒、25 个样本。
- 保持实际使用状态，没有重启壁纸、切换效果、暂停其他屏幕或模拟交互，也没有强制垃圾回收或修剪工作集。
- CPU 按整机 16 个逻辑处理器归一化；GPU 为进程对应的 3D 引擎计数。两者均根据原始累积计数的时间差计算。

整机同期 CPU 计数平均约 **25.6%**，物理内存已用约 **27.0 GiB / 47.9 GiB**；本项目只占其中一小部分。现有硬件传感器的 GPU 温度为 **58–61℃**。传感器采样窗口与进程计数不同，不应把百分比机械相加或互相替代。

### 内存上涨是否持续

主采样中私有提交量从 **437.5 MiB** 升至 **462.6 MiB**，因此追加观察了约两分钟。

追加采样中，该指标在 **432.4–463.1 MiB** 之间波动，平均 **448.5 MiB**，最后回落到 **436.0 MiB**。同一批进程未重启；其中 renderer 私有提交从追加采样起点的 **78.6 MiB** 回落到 **73.5 MiB**，GPU 进程从 **289.8 MiB** 回落到 **287.8 MiB**。

这表明本次短时上涨存在自然回落，**没有观察到单向持续增长**。仅凭这些进程计数不能确定是哪一种缓存释放或垃圾回收，也不能排除长时间运行后才出现的问题。

### 三种内存数值的区别

- **私有提交量**：进程申请的私有已提交虚拟内存，不等于全部驻留在物理内存中。
- **私有工作集**：当前驻留在物理内存中的私有页。
- **工作集合计**：还包含共享页；多个 CEF 进程相加可能重复计算共享部分，并受 Windows 内存管理影响。

它们是不同口径，不应相加；GPU 专用/共享内存也不能再机械叠加成项目独占内存总量。
